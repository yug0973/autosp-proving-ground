It has to fail first.

Before anything is changed, AUTOSP writes a test that exploits the finding and runs it against your code as it is. If the bug can't be reproduced, no patch is written.

Written where it can't reach anything.

A second agent writes the smallest fix it can, inside a throwaway container: no network, a read-only file system, a hard time limit.

Room 3. The Clean Room.
A sealed sandbox. Container, 2026. One line removed, one line added.

The patch

 def find_invoice(cur, invoice_id):-    cur.execute("SELECT * FROM invoices WHERE id = '" + invoice_id + "'")+    cur.execute("SELECT * FROM invoices WHERE id = %s", (invoice_id,))     return cur.fetchone()

The container is gone when the job ends.

Any one of three checks can send it back.

Every fix walks through the same three gates: the reproduction test has to pass now, your existing suite has to pass, and a fresh static scan has to come back clear. The agents can't reach these checks.

Room 8. Gallery Rules.
A GitHub App, on the repositories you choose. Nothing touches your code until you've signed a scope agreement.

AUTOSP may

  • Read the repositories you choose
  • Open pull requests on its own branches
  • Read your scanner's findings
  • Run code in a sealed sandbox

AUTOSP may not

  • Merge or approve
  • Push to main or to protected branches
  • Change repository settings
  • Keep your code after a job

GitHub App permissions and data retention: agreed per design partner.

Visitor information.

Room 10. Visitor Information.
The information desk. Ask anything else in the invitation's note.

Which languages does it work with?

The pilot is for Python services hosted on GitHub.

Which scanners does it take findings from?

Semgrep, CodeQL, Snyk Code and osv-scanner.

Can it merge by itself?

No. It opens pull requests with the evidence and stops there. Your reviewers approve and merge under your own branch protection, and the GitHub App can't change or bypass it.

Where does my code run?

In a throwaway container with no network, a read-only file system and a hard time limit. The container is gone when the job ends.
